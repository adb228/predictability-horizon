### Conventions followed so far

- **Roles (D-039, D-004, brief §0 and §7).** The owner derives and verifies the mathematics and must be able to defend every line; the agent implements all code. The agent explains the math first, conceptually, with the final equations and the tests that guard them, and for the Lyapunov estimators the owner derives and verifies before any code. Every commit that adds implementation says in its message that the agent wrote it, and docs-only commits say so too (messages: a short subject with a prefix such as `docs:`, `tests:` or `ci:`, and a body). Explanations stay short; say "I'm not certain" where that is true; when there are two reasonable options, give the trade-off in a few lines and a recommendation (brief §0). **Never fabricate, estimate or "illustrate" a result**: every number in the repository comes from a committed script, and numbers from a throwaway "lab" (calibration, mutants, timing) are labelled "uncommitted lab", their scripts and raw outputs are not committed (D-038), and the scratch folders are deleted afterwards. Timings taken on a busy machine are flagged as such.
- **The deferral rule (D-007, D-025).** The agent logs each larger decision in `docs/DECISIONS.md` **before** implementing it and sends it to a second-model design reviewer (called Opus 5.5 in the log; the implementer is called Sonnet 5.5). "Larger" means any of: (a) costly to reverse; (b) can silently change numerical results; (c) adds a dependency or a tool; (d) changes the public surface (module interfaces, CI semantics); (e) any change to a predeclared tolerance or gate threshold. An entry has the form Choice, "Opus 5.5 changed", Alternatives, Why, with the reviewer's verdict in its heading (APPROVE or AMEND). A milestone is reviewed twice: the design before any code, and the diff after CI is green. The second review must end in the explicit line `APPROVED FOR MERGE`: "reviewed" is not approval. Decisions that touch the owner's accounts or personal details are **not** sent to the reviewer; they go to the owner. In Claude Code the reviewer is the subagent of D-072.
- **Predeclared values and gate failures (D-025, D-031).** Tolerances, horizons, grids, state counts and seed streams are declared in `src/horizon/tolerances.py` and in the log before the code under test exists, and a tripwire test (K1 in each register test file) pins every value. If a frozen gate fails, **stop and report**; never adjust a threshold, grid, horizon or seed stream to make it pass. Seeds: `np.random.default_rng([CASES_SEED, stream])` with `CASES_SEED = 20261010`. Streams in use: 0 to 19 (the moderate parameter sets), 1000, 2000 to 2003 (milestone 3) and 3000 to 3006 (milestone 4); the calibration labs used a different first element (`[4343, k]`) and none of those was a gate stream. A new milestone takes a new block; 4000 and up is the natural next one, to be declared in its design entry. Per-test timeout 60 s (D-036): a test that needs longer carries a declared `@pytest.mark.timeout(N)`, logged first (E1 300 s, V1 regular 120 s). Every milestone so far followed the same pattern: a derivation note with a claim-to-test table, a register section with its tripwire test, shared helpers used by both the tests and the script, tests, and a script that prints the measured numbers with the git SHA of a clean tree.
